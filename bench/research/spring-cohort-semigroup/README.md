## Закон и направление вычисления

Для y=x-1, A=[[0,1],[-k/m,-c/m]] переход Phi(t)=exp(A*t) удовлетворяет Phi(t+h)=Phi(h)Phi(t). Прототип получает Phi(h) из исходного solver, не копируя три режима затухания.

Target-major stagger запрашивает убывающие локальные времена. Естественный обратный перенос опасен: инверсия восстанавливает уже подавленную быструю моду и усиливает ошибку округления. Finite/subnormal guard не закрывает этот класс.

Контрпример через полный публичный animate: m=1, k=400, c=800; две цели, stagger 99 ms, timestamps [0,100], x от 0 до 100 px. На второй цели baseline выдаёт x=0.015582570031802412 px и v=27.531735545939117 px/s; обратный кандидат x=-110063752768284260000 px. Это дефект кандидата, не main.

Независимая 80-разрядная матричная экспонента исходного ОДУ даёт x=0.015582570031807772... px. Обратный перенос на 99 ms имеет спектральный коэффициент усиления около 2.3693e34. Даже 80-разрядная инверсия уже округлённого binary64-якоря даёт x около 6.8975e16 px: потеря информации в позднем состоянии реальна, простое повышение точности умножения её не исправляет.

Для прямого направления G=diag(1,1/omega^2): A^T G + G A=diag(0,-4*zeta/omega). Энергетическая норма не растёт в точной вещественной арифметике. Это не универсальная оценка накопления binary64-ошибки.

Более сильный кандидат переставляет только contiguous spring compute-группы, оставляя render/write порядок прежним; переносит состояние вперёд и заново якорится каждый кадр. Две exact ячейки шага нужны из-за различных binary64-разностей времени. Никакой квантизации часов и замены near-critical на critical нет.

## Проверки семантики и упрощение

26/26 выбранных случаев сохранили записанные topology/order, число callback/write/completion и active units. Максимум численной дельты позиции 3.1752378504279477e-12 px, скорости 2.1316282072803006e-11 px/s. Проверены under/critical/over/near-critical, большой разрыв timestamps, pause/seek/play, successor из setter, бросок setter, reduced motion. Это конечный корпус, не доказательство произвольных interleavings; битовый паритет НЕ заявлен.

В forward-conformance.json историческое имя `guarded` означает FORWARD, а `unguarded` — GUARDED REVERSE. Скрипт сохранён без переименования полей выполненного эксперимента; это важно при чтении результата.

Mutation знака матричного элемента дала ошибку 102.187 px: контроль действительно отвергает дефект. Упрощение до одной ячейки сохранило проверенную арифметику, но для N=100/stagger=1 увеличило расчёты шага 737 -> 1279. Оно не сохраняет весь структурный выигрыш.

Offline Chromium 144.0.7559.96: три реальных DOM-сценария width/height, base/forward совпали с точностью CSS-сериализации. Это выполнение обёрнутой копии модуля на synthetic clock, не проверка ESM loader, compositor-residency, paint или трёх движков. Блокировка loopback администрацией не обходилась.

## Производительность и причинный контроль

Измеряется реальный animate planner + scheduler + 60 mock-host кадров + cancel/finished/drain; DOM/paint отсутствуют. Два отдельных процесса, 24 ABBA/BAAB-блока на каждую из семи сцен, шесть warmups на вариант/сцену. Внутри блока A и B усредняются отдельно; итог — медиана парных (B/A-1). Не отношение двух непарных медиан. Bootstrap 20000 resamples, seed 20260906, pointwise 95% intervals; поправка множественных сравнений и глобальное superiority admission НЕ выполнены.

Чистый counter-free candidate SHA-256: `291c5e1dc0d28e1e0771032363dec24cbee831c258f0c926f3eca663f06943b6`. Имя generated-файла `release` обозначает снятие диагностики, а не выпуск продукта.

Все start/frame/total summaries, включая проигрыши малых сцен, в timing-summary.csv. N=1/stagger=1: парная start-дельта +14.23% и +30.22%; малые времена и шум не превращаются в универсальный performance claim.

Нельзя приписать coherent-ускорение полугруппе: на этой сцене переносов НОЛЬ, solver calls всё ещё 60. Поэтому проведён дополнительный причинный контроль A=original/O=только порядок/F=полный кандидат: два отдельных процесса, 18 сбалансированных блоков всех шести порядков на три сцены. F/A по frame: coherent -1.97%/-0.01%; dense stagger +4.64%/+1.72%; wide stagger +5.62%/+6.51%. Интервалы всех этих F/A включают ноль. O/A тоже не даёт общего устойчивого выигрыша. Другой состав call-site не воспроизвёл предыдущую величину эффекта; конкретная причина JIT/системного шума не доказана. Выбирать только удачные ABBA-цифры нельзя.

Два начальных 16-блочных прогона ошибочно включали диагностические счётчики только у candidate: исключены из приёмки, а не скрыты. Чистые 24-блочные прогоны выполнены после удаления счётчиков. У clean-1 исправлено только устаревшее текстовое поле «16» -> «24»; observations не менялись, correction записан в JSON.

## Границы NO-GO

Обратный перенос округлённого общего состояния опровергнут конкретным обычным физическим входом. Весь phase-shift класс и устойчивые модальные/offline представления этим НЕ исключены.

Прямой prototype — NO-GO к поставке: нет подтверждённого системного non-regression; добавлено 80 B числового банка плюс объекты/поля на batch и обход внутренних MainUnit-полей для классификации чистого compute. Это неоплаченная память и архитектурная цена. Такой reach-into нельзя переносить в production. Отсутствующий CI не является математическим опровержением.

Основание для возвращения: представление, использующее существующее владение/буферы без нового retained-состояния, либо иной доказанный способ устранить повторную работу без перестановки эффектов; затем полный внешний семантический и performance контроль. Один факт «меньше exp» такого основания не заменяет. #242 остаётся владельцем широкого направления; product defect в baseline не объявлен.

ДА: настоящий packed runtime, конечный differential corpus, mutation, независимый численный/символьный oracle, повторные измерения и causal control. НЕ БЫЛО: source integration, canonical rebuild/size/import-cost, полный repository suite, Firefox/WebKit, candidate exact-SHA remote gates, независимое code review. Green CI входного пакета не является green CI кандидата. Src/tests/gates/default branch не изменены. Production PR/merge/auto-merge не создавались.

## Воспроизведение

Поместить исходный CI npm-пакет в `package/` рядом со скриптами. Нужны оригинальные dist/animate/index.js, dist/frame/index.js и package.json; первый файл проверяется по SHA-256. Полный комплект исходных байтов и первичных JSON передан отдельным архивом пользователю. Git хранит скрипты, воспроизводимый численный свидетель и производные summaries; не заявляется, что большие первичные JSON загружены в Git.

```sh
node make-candidates.mjs
node forward-conformance.mjs
node controls.mjs
python independent-oracle.py
node paired-release.mjs replay-a 24
node paired-release.mjs replay-b 24
node causal-control.mjs replay-a
node causal-control.mjs replay-b
```

Python oracle использует mpmath 1.3.0 и SymPy 1.14.0. Node-скрипты не добавляют production dependency. Они создают только research-копии внутри исследовательского package/dist; исходный index.js не заменяется. Тесты исходного репозитория не редактируются и не исключаются.
