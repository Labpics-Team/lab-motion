Более дешёвые альтернативы оценены по требуемому исходу. `process.threadCpuUsage()` уже имеет первичный контрпример. `process.cpuUsage()` расширяет область до всего процесса; wall `hrtime/performance.now` включает scheduling и меняет CPU proposition; helper/IPC или perf создают дополнительную границу и не дают те же endpoints внутри текущего JS owner; сторонний native npm addon добавляет supply/build closure. Сохранить UNPROVEN без getter — допустимое отсутствие CPU допуска, но оно не достигает заказанного серверного измерения. Малый private NAPI getter в существующем profile owner является соразмерным решением. Prebuilt/cache reuse может экономить компиляцию, однако его отдельная квалификация сейчас дороже запрета stale output.

Два существенных предела сохранены явно. `cc` hash/version/flags не включает cc1/as/ld, CRT, system-header bytes и полную build environment; actual binary hash связывает именно наблюдённый выход. Для частного наблюдения reported counter на закреплённом Node/Linux/libc это не подтверждённое нарушение применимой обязанности; расширение утверждения или счётчик/символ, не соответствующий зарегистрированной модели, переоткроет affected review. Linux x64/glibc/main-thread и точный Node являются ограничением стенда; musl/ARM/macOS/Windows требуют новой qualification и не получают перенос по названию часов.
