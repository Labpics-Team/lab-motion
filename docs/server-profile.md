# Запустить серверный профиль и проверить результат

Практическое руководство для сравнения двух checkout: время исполнения потока
Node, сообщаемое Linux, и стоимость публичного API в браузере.

## Подготовка и запуск

Платформу, версии инструментов и исходный checkout задаёт
[`SERVER_PROFILE`](../bench/profile/server-profile-registration.mjs).
Установите зависимости корня и `bench/compare` по зафиксированным lock-файлам;
указанные Node и pnpm должны быть первыми в `PATH`. Нужны компилятор C11 и Linux libc.
Оба checkout должны быть чистыми. На время измерений освободите хост от других проверок.

```sh
taskset -c 0 node bench/profile/server-profile-runner.mjs \
  --baseline /path/to/baseline --candidate /path/to/candidate \
  --browser chromium --out /outside/checkout/server-chromium-registration-1
```

Каталог результата должен отсутствовать и находиться вне checkout. До измерений
инструмент проверяет ресурсы хоста, исходники, часы и собранные пакеты участников.
Потребители используют упакованные пакеты. Повтор серии ради успешного исхода запрещён:
смена метода требует новой регистрации с сохранением прежних данных и отказов.

## Проверьте сохранённый результат

Каталог содержит `server-profile.json`, `server-profile.sha256`, `journal.ndjson`,
исходные контрольные данные, пакеты и сведения о сборке счётчика. Все приобретённые
наблюдения и частичные результаты ошибок сохраняются. Для независимой проверки
передайте отдельно сохранённый digest и журнал:

```sh
node bench/profile/server-profile-artifact.mjs \
  --raw /outside/checkout/server-chromium-registration-1/server-profile.json \
  --digest '<64 hex из независимо сохранённого server-profile.sha256>' \
  --journal /outside/checkout/server-chromium-registration-1/journal.ndjson
```

Проверка связывает исходные данные с digest и журналом. При интерпретации отчёта
учитывайте его `verdict` и границы измерения ниже: сохранённый отказ остаётся отказом.

## Определите область результата

Числовые параметры и правила допуска принадлежат исходникам:

- [`SERVER_PROFILE`](../bench/profile/server-profile-registration.mjs) — сцены,
  объём работы, модель часов, выборка и условия остановки.
- [Контракт профиля](../bench/profile/server-profile-contract.mjs) — проверка данных,
  происхождения результата, последовательности этапов и статистических границ.
- [Методология сравнения](../bench/compare/methodology.mjs) и
  [владелец измерения](../scripts/bench-transform-support.mjs) — независимая проверка
  полезного движения, завершения и отмены.

`CLOCK_THREAD_CPUTIME_ID` наблюдает сообщённое ядром время исполнения главного потока.
Наружное расширение счётчика учитывается при допуске; оно не удостоверяет физическую
точность часов. Номинальное разрешение `clock_getres` также не задаёт точность.
Накладные расходы чтения включены. Требования к сборке и происхождению счётчика —
в [справочнике его исходников](../bench/profile/native-clock/README.md).

Браузерное измерение наблюдает истекшее время вызова API через `performance.now`,
включая влияние планировщика и сборки мусора. Результат относится к агрегату блока;
он не доказывает задержку отдельного вызова, кадровую частоту, стоимость GPU,
энергопотребление или поведение физических Android/iOS. Функциональные проверки
Firefox/WebKit не заменяют измерение с зарегистрированной моделью часов.

Неразрешимое наблюдение, ошибка или нарушение ресурсных условий дают `UNPROVEN`.
Если пилот требует выборку выше предела, инструмент сразу сохраняет отказ.
`SIGINT`/`SIGTERM` завершают текущее измерение, сохраняют полученные данные и закрывают
ресурсы; следующие измерения не запускаются.
Подавленные адаптером исключения внешнего исполнителя наблюдать невозможно.
Принудительная сборка мусора применяется только в отдельной проверке оставшейся
памяти после измерений; её стоимость не включается в измеренный интервал CPU.

Допущенный результат действует только для зарегистрированного набора исходников,
пакетов, инструментов и метода. Планы исполнения находятся в
[agents-config](https://github.com/Labpics-Team/agents-config/tree/main/plans/lab-motion-production);
для интерпретации конкретной серии используйте её регистрацию и исходные данные.
