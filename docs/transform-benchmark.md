# Парное измерение transform через публичный API

`scripts/bench-transform-pair.mjs` сравнивает два чистых checkout через
`dist/animate/index.js`. Область измерения — движок в Node: линейный tween,
ручные часы кадров и объекты с `style.setProperty`. DOM, браузерная отрисовка,
нативная анимация и стоимость сборки мусора отдельно не измеряются.

```sh
node scripts/bench-transform-pair.mjs --baseline /path/to/baseline --candidate /path/to/candidate > /outside/checkout/transform-pair.json
```

Runner и оба измеряемых дерева должны быть чистыми. Зависимости устанавливаются
заранее через `pnpm install --frozen-lockfile`; версия Node — 24, версия pnpm
закреплена в `packageManager`. Скрипт пересобирает оба дерева до первого измерения.
Логи сборки направлены в stderr; stdout содержит один JSON после проверки
неизменности checkout, dist, инструментов сборки и файлов стенда. Одинаковый
фактический путь baseline/candidate и дополнительные аргументы отклоняются.

| Поле профиля | Значение |
| --- | --- |
| Цели | 1, 100, 1000 |
| Состояние | fresh: без предыдущего вызова; settled: после естественного завершения; live: перехват на 32 мс |
| Каналы | предыдущие 7 → следующий x либо все 7: x, y, scaleX, scaleY, rotate, skewX, skewY |
| Tween | linear, 128 мс |
| Измеряемые кадры | 0, 16, 32, 48, 64, 80 мс относительно первого кадра следующего вызова |
| Прогоны на сценарий | 2 прогрева и 8 измерений, полный блок AB/BA |
| Начальное число | `0x7472616e` |

Начальные и конечные значения записаны в `profile`. Каждый sample создаёт
собственные цели; settled/live повторно используют их внутри sample.
Подготовка предыдущего состояния, создание входов и проверка результатов
находятся вне измеряемых интервалов. `operationNs` содержит один публичный
`animate`, `frameNs` — отдельные кадры, `cancelDrainNs` — cancel и выполнение
уже поставленного callback. Работа сохраняющего трассу `style.setProperty`
включена в стоимость кадра.

Независимая формула linear проверяет все семь значений каждого target на каждом
кадре, включая замороженные остаточные каналы. Проверяются число записей,
`finished`, `onComplete` и отсутствие работы после cancel. Семантический сбой
или изменение закреплённых файлов отклоняет весь результат.
Профиль требует порядок translate → scale → rotate → skew; две оси skew
задаются одной функцией. Перестановка сохраняет числа, но меняет CSS-матрицу.
Другой способ сериализации требует отдельной проверки эквивалентности профилю.

`raw` сохраняет прогрев, порядковый номер прогона, идентификатор парного блока,
порядок участников, времена и SHA-256 трассы каждого target. `summary` использует
только измерительные прогоны: p50/p95/p99 ближайшего ранга для операций,
объединённых кадров и отмены. Кадры одного sample зависимы; восемь наблюдений
операции дают лишь предварительное сравнение, p95 и p99 совпадают с максимумом.
Это эмпирические квантили без доверительных границ и без доказательства хвостовой
латентности. Порога ускорения, статуса превосходства и сертификации общей
производительности в отчёте нет.
