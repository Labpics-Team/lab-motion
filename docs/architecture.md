# Архитектура движка

## Публичная модель

Root API описывает цели, траектории и время жизни. `Program` содержит проверенные
значения и исходную шкалу; `Runtime` владеет каналами; `Surface` собирает одну
CSS-запись из независимых каналов. Код живёт в `src/motion` и использует
существующие численные решатели, CSS-парсеры и общий кадровый планировщик.

Нативная анимация и JavaScript используют один план и один реестр владельцев.
Для transform нативное исполнение допустимо при совместимых кривых и шкалах всех
осей. Разные шкалы, цвета, многоточечные траектории и неподходящие CSS-свойства
используют JS. Выбор происходит внутри; публичные контролы не раскрывают
идентификатор исполнителя.

Новая цель получает актуальные положение и скорость. Повтор совпадающей цели
передаёт управление, сохраняя исполнение. Прежний controller лишается права
управлять переданным каналом. Число владельцев канала остаётся ограниченным.

Завершение очищает tracks, callback-подписки и нативный эффект до разрешения
`finished`. Последняя кадровая подписка снимает и browser reservation. Завершённые
контролы можно хранить, не удерживая через них элементы и компоненты.

`scope` владеет пользователями этого протокола, но не дублирует реестр каналов.
Ручной `dispose` дочернего ресурса сразу удаляет запись родителя. `layout` имеет
отдельную границу: обновление приложения и временные снимки View Transitions.
Оно не подменяет изменение ширины визуальным масштабированием.

## Проверка изменений

Публичные сценарии проходят через собранный root ESM, установленный tarball,
CommonJS и типы TypeScript. В браузерах проверяются геометрия, прерывание,
пауза, исходная шкала, reduced motion, раскладка и очистка. Дифференциальные
последовательности сопоставляют native и JS; отдельный GC-прогон сохраняет
терминальные контролы и проверяет освобождение компонентов.

Ниже описаны сохранённые низкоуровневые модули и их численные границы. Они
обслуживают свои прямые потребители; root API не требует выбора этих модулей.

## Граница с компонентами

Движок владеет значениями, временем, скоростью, прерыванием и завершением движения.
Приложение задаёт цели и ограничения: точки остановки панели, выбранную страницу,
порог действия, доступность и запрос обновления. Изменение этих правил остаётся
локальным для компонента.

`./behaviors` разрешает произвольные слои целей, `./behaviors/reorder` предлагает
порядок по ключам и геометрии, `./compositor/follow` принимает прямой ввод и цель
доводки. Примеры компонентов находятся в [рецептах](recipes.md) и приложениях
`examples/`; они используют публичные примитивы и не входят в runtime пакета.

## Слои

Слои снизу вверх; клятва «ядро не знает про DOM» держится на каждом уровне:

1. **L1 — чистая физика** (zero-dep, headless): `spring` — closed-form солвер;
   `easing`/`value`/`utils` — математика значений.
2. **Драйверы значений (главный поток)**: `MotionValue` — smooth pickup;
   `drive`/`createDriver` — scrub, thenable. Питаются солвером и математикой.
3. **`frame`** — единый rAF-шедулер (read → update → render), на нём едут оба
   драйвера.
4. **Потребители**: 9 биндингов (8 optional peer; `./wc` без зависимостей)
   поверх шедулера — либо пружина целиком уезжает на compositor-поток:
   адаптивный план WAAPI → `Element.animate` прямо из солвера
   ([compositor.md](compositor.md)).

Рендер всегда делает потребитель (колбэк или биндинг); время приходит через
инжектируемый `requestFrame`. Два следствия: движок тестируется на виртуальном
времени бит-в-бит, а SSR-импорт любого субпутя не трогает `window`/`document`.

## Фазовая модель движения

Интерактив и фаза слежения (палец ведёт значение) — на главном потоке
(`MotionValue`, `drive`, `./gestures`). Автономные переходы и release-фаза —
compositor-путь (`./compositor`, `./waapi`): пружина компилируется в
адаптивный WAAPI-план и живёт на compositor-потоке; главный поток не будится
до завершения. Границы, ретаргет и хендофф — [compositor.md](compositor.md).

## Инварианты (гарантии потребителю)

- **Zero-deps**: в `package.json` нет поля `dependencies` — фреймворки только
  как optional peer у биндингов.
- **CSS-safe**: движок никогда не отдаёт `NaN`/`Infinity` — числовые слои под
  property-fuzz на 10 000 входов, spring-солвер — под отдельным seeded-fuzz по
  рабочему боксу валидного пространства (mass/stiffness/damping/t, включая
  нижние края).
- **Детерминизм**: время только через инжектируемый `requestFrame` — бит-в-бит
  воспроизводимые прогоны.
- **SSR-safe**: импорт любого субпутя не трогает `window`/`document`.
- **A11y**: `prefers-reduced-motion` переключает характер (снап/фейд), не
  отключает движение грубо.
- **Запинённый контракт**: api-surface-pin тесты держат публичную поверхность
  субпутей — пропавший И лишний экспорт даёт красный тест.

## Отвергнутые пути (контрфакты, НЕ реализованы)

Отвергнуты с доказательствами — задокументированы, чтобы не переизобретать:

- **WASM/SIMD для одиночных DOM-пружин** — переход JS↔WASM не убирает DOM-
  запись и добавляет границу вызова; SIMD раскрывается на больших однородных
  батчах, а не на одной автономной анимации. Hot-path остаётся в JIT-доступном JS.
- **GPU compute (WebGPU)** — не может писать в DOM без readback-stall; выигрыш
  только для canvas/WebGL при 10k+ объектов.
- **Движок в Web Worker + SharedArrayBuffer** — не снижает input→photon для DOM
  (+hop `postMessage`); SAB требует COOP/COEP, ломающих сторонние embed'ы.
- **Анимация CSS custom properties как «compositor-путь»** — `@property`/`var()`
  не ускоряются на compositor и триггерят style-invalidation каждый тик.
- **Ретаргет мутацией `playbackRate`/`currentTime`** — по W3C Web Animations L1
  (§4.4.4, §4.4.15) и MDN обе операции живут в timing model и не трогают
  `KeyframeEffect`: `playbackRate` — скаляр скорости вдоль запечённой кривой,
  `currentTime` — seek по ней. Ретаргет пружины требует НОВОЙ точки равновесия и
  профиля скорости из текущих (pos, vel) — это новый `KeyframeEffect`, поэтому
  cancel + рекомпиляция через кэш + re-emit необходимы, а не упущенная оптимизация.

Перф-путь аналитический (O(1) на кадр, closed-form солвер). Wall-clock числа
машинозависимы и справочны (`pnpm bench`); проверяемый seal — тесты:

- interior error компилированной кривой ≤ tolerance, CSS/WebKit parity;
- effect-space continuity вне stop-kink;
- `test/perf-hot-path.test.ts`: кадры до сходимости = вызовы солвера
  (машинонезависимый инвариант работы).
