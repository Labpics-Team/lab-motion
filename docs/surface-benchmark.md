# Парное измерение Surface-компилятора

## Назначение

`scripts/bench-surface-pair.mjs` сравнивает полную публичную операцию
`motionCompiler().transform`: parse, проверку допустимости, компиляцию сопряжённых
кривых, генерацию кода и sourcemap. База и кандидат собираются заново из чистых
Git checkout одной инструментальной цепочкой. Существующие законы provenance и
парного bootstrap используются напрямую, а не переписываются для этого стенда.

Это Node-измерение компилятора, не браузерный стенд. Оно не заменяет
[сравнение браузеров и общие правила](benchmark.md), независимые numeric/semantic
проверки, size/import gates или измерение удерживаемой памяти.

## Воспроизведение

Нужны Node 24, точный pnpm из `packageManager` и установленные по lock-файлу
зависимости в обоих checkout. Версии Node executable, реальных деревьев
TypeScript/esbuild/Terser/tsup/pako/Acorn и Git фиксируются в результате.

```bash
# Выполняется из отдельного чистого checkout со стендом.
# В обоих сравниваемых checkout заранее: pnpm install --frozen-lockfile.
node scripts/bench-surface-pair.mjs \
  --base /path/to/baseline \
  --candidate /path/to/candidate \
  --out /path/to/reports/new-surface-run

# Только контроль пригодности среды, без кандидата:
node scripts/bench-surface-pair.mjs \
  --base /path/to/baseline \
  --out /path/to/reports/new-calibration \
  --calibrate-only

# Независимый пересчёт summary и verdict из полного raw journal:
node scripts/bench-surface-pair.mjs --verify /path/to/reports/new-surface-run
```

Родитель выходного каталога должен существовать, сам каталог — ещё нет. Старый
результат не перезаписывается. Код возврата `2` означает `UNPROVEN`, не успешное
performance admission; ошибка выполнения или происхождения данных завершает
процесс ненулевым кодом. `--verify` подтверждает пересчёт сохранённых данных,
не утверждает заново подлинность исходного стенда или пригодность чужой машины.

## Измеряемая граница

В отдельные файлы копируются **неизменённые байты** самодостаточного публичного
`compiler/vite` entry. Приватная функция не извлекается, не копируется и не
де-инлайнится: это изменило бы фактически измеряемую программу. Если entry
получает imports, стенд останавливается до измерения: тогда необходимо явно
поддержать весь граф, а не тайно измерять его неполную копию.

Каждый независимый кластер — новый Node-процесс с двумя module identities.
A/A использует две одинаковые копии entry; A/B — копии базы и кандидата с такой
же топологией. A/A не разделяет один cache/function там, где A/B получает два.
Порядок четырёх bursts чередуется ABBA/BAAB. Внутренние вызовы одного burst не
считаются независимыми наблюдениями.

Прогрев и измерение используют один batch call-site. Фиксированная warm-фаза
принадлежит manifest, а не подбирается по результату кандидата. Она не является
универсальной гарантией завершения JIT: калибровка обязательна на каждой машине.
В publish-прогоне запрещены `NODE_OPTIONS`, дополнительные Node flags, принудительная
оптимизация и ручной GC. Tracing подходит для отдельной диагностики причин,
но его время нельзя смешивать с publish samples.

## Сценарии и фазы

Единственный manifest в `scripts/bench-surface-support.mjs` определяет обычную,
колебательную, сильно затухающую, восьмицелевую, большую и вырожденную программы;
также проверяется отказ компиляции при превышении бюджета. Динамический вызов и
модуль без относящегося к библиотеке импорта служат отдельными no-op controls.
Для последнего заранее задан более длинный burst: иначе стоимость чтения таймера
сопоставима с практически пустым вызовом. Counts не подбираются по candidate ratios.

Для каждого содержательного сценария есть два состояния кэша:

- `warm`: повторяется одна и та же программа;
- `miss`: циклически меняются 512 точных параметров жёсткости, без `clear()` и без
  повторения кэш-ключа до истечения bounded cache. JIT при этом **прогрет**.

`miss` — не cold application startup. Network/import/parse самого пакета, первая
операция нового JS realm, main-thread execution анимации, DOM/layout/paint и
input-to-pixel здесь не измеряются. Ненулевая скорость и отдельный private
coupling-budget не выдумываются как поддерживаемые статические публичные опции.
Исторические private-stage замеры не превращаются в результат нового стенда.

`return` включает вызов transform и чтение длины результата. `consume` дополнительно
читает все UTF-16 units кода, mappings, sources, sourcesContent и names. Эти
операции публикуются отдельно: ленивые строки не позволяют объявить полный
жизненный цикл измеренным по одному API-return.

Перед timing база и кандидат должны дать одинаковые полные code/map на всех
программах. Ожидаемые lowering/отказы проверяются отдельно, чтобы два сломанных
no-op не прошли как эквивалентная быстрая реализация. Каждый burst дополнительно
сверяется с заранее вычисленными результатами вне своего timed-window.

## Калибровка и решение

Сначала выполняются только A/A для ordinary warm/miss full-consume,
реального бюджетного отказа и восьмицелевого transform; затем deliberate
positive control с двойным числом операций при прежнем per-request знаменателе.
Все confidence intervals равенства должны содержать 1; upper p95 не выше 1.05.
Positive control обязан уверенно обнаруживать дополнительную работу.

Если хотя бы один контроль не разрешает разницу, candidate timing **не начинается**.
Результат остаётся `UNPROVEN`. Нельзя повторять ту же конфигурацию до благоприятного
исхода, отбрасывать медленные samples, менять число операций или увеличивать
margin после просмотра данных. Исправление среды/метода требует нового
объясняющего факта и предварительной регистрации в существующем research issue.

После калибровки выполняется один полный проход всех candidate-профилей.
`LATENCY_ADMISSION` означает только upper CI p95 ≤ 1.05 в данном envelope.
Это не абсолютное отсутствие регрессии и не автоматическая публикация speed-win:
для победы по скорости дополнительно действуют общий practical threshold,
разрешимость таймера и семантические требования из `docs/benchmark.md`.
Неопределённость хотя бы одного профиля оставляет `UNPROVEN`.

## Доказательства и защита стенда

`manifest.json` фиксирует ревизии, профиль, checksum инструментов и измеренных
entry-файлов. `raw.jsonl` дописывается после каждого независимого кластера,
включая все медленные observations; исходные elapsed ns и делитель сохраняются.
Worker сохраняет 64 пары последовательных timer reads до/после и resource counters.
Это наблюдения неопределённости, не разрешение вычитать clock, GC или переключения
контекста из измеренного wall-clock времени.
`summary.json` производен от raw через общий paired cluster bootstrap.
`verdict.json` не заменяет raw, а `--verify` повторяет группировку и вычисление:
пропущенные, повторённые, переставленные, нечисловые или лишние observations
отвергаются. После прогона повторно проверяются Git, dist, node_modules и файлы
самого стенда. Ошибка происхождения данных не является NO-GO алгоритма.

`test/bench-surface-pair.test.ts` работает без wall-clock порогов: виртуальный
clock доказывает границы warmup/timing, точное количество вызовов и удвоение
работы; реальные corrupted-output controls проверяют fail-closed поведение.
Этот стенд не заменяет отдельный main-thread transform lifecycle benchmark:
тот измеряет исполнение анимации и форматирование кадра, а не Vite lowering.
