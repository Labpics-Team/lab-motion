# Движение из состояния приложения

`createMotionBinding` связывает состояние приложения с анимациями. Вы описываете
визуальные цели один раз, затем передаёте новые данные через `update`. Привязка
запускает только изменившиеся роли и отменяет принятые анимации при `destroy`.

```typescript
import { animate } from '@labpics/motion/animate';
import { createMotionBinding } from '@labpics/motion/bindings';

export function bindProgressMotion(fill: HTMLElement, label: HTMLElement) {
  return createMotionBinding(
    (state: { progress: number; active: boolean }) => ({
      fill: { scaleX: state.progress },
      label: { opacity: state.active ? 1 : 0 },
    }),
    {
      fill: goal => animate(fill, goal),
      label: goal => animate(label, goal),
    },
  );
}
```

Для полосы задайте CSS `transform-origin: left center`. Приложение передаёт
`progress` от 0 до 1 и отвечает за текст, доступность и состояние загрузки.

```typescript
const motion = bindProgressMotion(fill, label);
motion.update({ progress: 0.25, active: true });
motion.update({ progress: 0.5, active: true });
// Обновится только fill; анимация label продолжится.

motion.destroy();
```

Типы целей выводятся из первой функции. Имена исполнителей должны совпадать
с именами ролей: опечатку или пропущенную роль обнаружит TypeScript.
Дополнительные примеры: [загрузка](recipes.md#карточка-загрузки-одна-модель-разные-движения)
и [навигация с независимым фокусом](recipes.md#навигация-выбор-и-клавиатурный-фокус-независимы).

## `createMotionBinding(project, targets)`

Чистая функция `project(model)` возвращает именованные цели. Карта `targets`
связывает каждую роль с исполнителем: `animate`, существующим `MotionValue`
или собственным renderer. Функция исполнителя получает всю цель роли и может
вернуть объект с `cancel()`. Привязка берёт его очистку на себя.

Исполнитель, возвращающий `void`, оставляет управление ресурсом приложению.
Это подходит для уже существующего `MotionValue`. Проекция зависит только
от переданной модели; изменившееся замыкание или CSS-переменная сами по себе
не вызывают обновление. Привязка вычисляет цели при `update`, без подписки
на модель и без собственного кадрового цикла.

## `update(model)`

Вызов сначала вычисляет и проверяет все цели, затем обновляет исполнителей.
Модель приложения не сохраняется. Входные объекты можно менять между вызовами:
привязка каждый раз читает их свойства и проверяет значения.

Каждая изменённая цель копируется в поверхностно замороженный снимок.
Неизменённые роли используют прежние снимки; им не нужны новые копии или
замораживание. Дальнейшая мутация входного объекта не затрагивает принятые цели.

Правила входа:

- Карта ролей совпадает с картой исполнителей. Первый корректный снимок задаёт
  набор свойств каждой роли; последующие сохраняют его. Порядок ключей свободный.
- Учитываются собственные перечислимые строковые ключи. Значения содержат
  конечные числа или строки, без вложенных объектов.
- Суммарно допускается до 10 000 ролей и свойств в одном снимке.

Первое обновление вызывает всех исполнителей. Последующие сравнивают значения
через `Object.is` и передают только изменённые роли. Повтор прежнего состояния
сохраняет продолжающуюся анимацию.

Держите связанные transform-оси в одной роли: исполнитель получает и новую
цель `x`, и сохраняющуюся цель `y`. Это позволяет продолжить движение всей
поверхности при изменении одного её свойства. Разные исполнители должны
управлять непересекающимися выходами; их пересечение привязка не обнаруживает.

Для повторяемого действия, например встряхивания после ошибки, вызывайте
анимацию по событию. Равные цели состояния намеренно пропускаются. Строки
передаются исполнителю без интерпретации; относительные команды вроде `+=10`
тоже выполняются только при изменении строки цели.

## Прерывание и очистка

Все новые анимации создаются до отмены прежних. `animate` успевает подхватить
текущие положение и скорость. Одинаковый handle, переданный несколькими ролями
или повторно возвращённый исполнителем, отменяется один раз и продолжает жить,
пока его использует хотя бы одна роль.

Привязка сохраняет не более одного handle на роль, включая естественно
завершившийся: например, нативная `Animation` с `fill` сохраняет эффект после
`finished`. Поэтому `cancel()` должен оставаться безопасным после завершения.

`destroy()` отменяет принятые ресурсы и освобождает проекцию, исполнителей
и снимки. Повторный `destroy` и последующие `update` ничего не делают
и не читают новые аргументы. Исходный CSS, удаление DOM и восстановление
состояния остаются под управлением приложения.

## Вложенные обновления и ошибки

Вложенный `update` из исполнителя или `cancel` сразу снимает свои цели и доставляет
их после текущего обновления, в порядке вызовов. В том числе сохраняется возврат
к прежнему состоянию. Привязка не объединяет эти переходы и не ограничивает
бесконечную обратную связь.

Проекция должна быть чистой. Вызов `update` из неё или getter её результата
выбрасывает `LM181`. Ошибка проекции либо валидации оставляет прежние анимации
работающими; исходное исключение сохраняется, включая `throw undefined`.

Ошибка исполнителя или отмены завершает привязку с `state === 'failed'`.
Она пытается отменить все доступные старые и новые ресурсы; несколько ошибок
возвращаются в `AggregateError`. За ресурс, который бросивший исполнитель
не успел вернуть, отвечает сам исполнитель. Уже совершённые внешние эффекты
сохраняются.

`destroy` сначала устанавливает `state === 'destroyed'`, затем отменяет ресурсы.
Позднее исключение из вложенного вызова сохраняет это терминальное состояние.

| Код | Причина |
| --- | --- |
| `LM179` | Некорректная проекция, карта исполнителей или возвращённый handle |
| `LM180` | Некорректная форма либо значение цели |
| `LM181` | Вложенное обновление во время вычисления проекции |

## Стоимость обновления

Каждый `update` вызывает проекцию один раз и линейно проверяет её результат.
Повторное состояние обходится без новых снимков целей и вызовов исполнителей.
Изменение одной роли создаёт снимок только этой роли. Пользовательский код
проекции и проверка входа продолжают выполняться при каждом вызове.

Движение между обновлениями выполняет выбранный исполнитель. Привязка
не добавляет к нему кадры, таймеры или отдельную физику. Неиспользуемый
`@labpics/motion/bindings` не увеличивает остальные точки входа.
