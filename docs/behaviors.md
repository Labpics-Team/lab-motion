# Behaviors-путь

> Роль: контракт `./behaviors` — независимые от представления машины мобильных
> взаимодействий и каскад целевых значений поверх примитивов движка.

Субпуть только оркеструет — ничего не дублируется: трекер скорости из
`./gestures`, проекция момента из `./decay`, пружинный солвер ядра,
темп-токены `./tokens`. Поведение не знает про фреймворк/компонентную
библиотеку: DOM-обвязка — тонкий адаптер поверх headless-API
(runnable-пример — [recipes.md](recipes.md)).

Общий контракт четырёх мобильных поведений: `BehaviorState { value, velocity, phase }`,
`phase ∈ 'idle' | 'follow' | 'release' | 'settle'`. Вход — `pointerDown`/
`Move`/`Up`/`Cancel` с точкой `{ x, y, t }` (`t` — секунды, напр.
`e.timeStamp / 1000`); выход — `state`-геттер + `subscribe`; программные
переходы и идемпотентные `cancel()` / `destroy()`.

## Четыре поведения

- **`createBottomSheet`** — snap-точки, rubber-band за крайними snap,
  программный `snapTo(index)`, перехват новым pointer-down; `update(snapPoints)`
  меняет живые ограничения внутри того же owner без сброса позиции/скорости.
- **`createDragDismiss`** — порог по смещению ИЛИ скорости, настраиваемое
  направление, возврат с унаследованной скоростью при недостигнутом пороге,
  детерминизм при `pointerCancel` (всегда домой, без закрытия).
- **`createCarousel`** — index выводится из position каждый кадр, inertia с
  доводкой к странице, RTL и вертикаль, `goTo`/`next`/`prev`;
  `update(pageCount, pageSize)` сохраняет живой owner и логическую цель.
- **`createPullToRefresh`** — резистентный overscroll, порог активации,
  `pending` БЕЗ второго владельца позиции (удержание — тот же единственный
  runner), возврат пружиной после async-действия.

Runnable DOM-адаптер bottom sheet (transform из headless-состояния, полная
связка pointer-событий, программный `snapTo`) — в [recipes.md](recipes.md).

## Ключевые свойства (все запинены тестами)

- **Один clock (одна state machine)**: pointer / programmatic control не плодят
  параллельных loops — единый generation-токен гасит stale-кадры, активен
  максимум один runner. Перехват pointer-down во время доводки → `follow` без
  утечки цикла.
- **C¹ на стыке follow→release**: скорость момента отпускания наследуется
  доводкой (`v0n = velocity / range` в пружинном солвере) — как smooth-pickup
  у `MotionValue`.
- **Живые constraints принадлежат behavior-owner**: resize/update во время
  `follow` сохраняет наблюдаемую позицию и переякоривает тот же жест, а во время
  `release` тот же runner переназначает цель из текущих `(value, velocity)`;
  stale generation остаётся инертным, отдельный consumer-store не нужен.
- **Выбор цели по положению+скорости**: snap/страница выбираются по проекции
  момента через `./decay` (`.rest`) — быстрый флик перепрыгивает snap;
  property-тесты (seeded-LCG) пинят «ближайший к decay-landing» на диапазоне
  value+velocity.
- **Reduced-motion = смена характера**: пространственная доводка снапает в
  цель МГНОВЕННО (ни одного кадра), состояние и результат сохранены — не
  «выключение».
- **Финитность и SSR-safe**: `value`/`velocity` всегда конечны (никогда
  NaN/∞, `-0` схлопнут — фаззинг-тест злого ввода), импорт не трогает
  window/document; единственный платформенный шов — инжектируемый
  `requestFrame` (детерминизм тестов).
- **`cancel()`/`destroy()` идемпотентны**: `destroy` делает вход инертным.

## Каскад визуальных намерений

`createStateCascade<T>()` выбирает цель каждого свойства из приоритетных слоёв.
Например, нажатие может определять масштаб, а выбранное состояние — фон.
Снятие верхнего слоя раскрывает последнее значение нижнего. Перекрытые изменения
сохраняются без уведомлений. Движение и доступность обеспечивает исполнитель,
например `MotionValue`; у каскада нет DOM, часов или физики.

| Операция | Действие |
|---|---|
| `state.createLayer(initial?)` | Создаёт слой выше ранее опубликованных. Без `initial` слой неактивен; `{}` активен, но ничем не владеет. Создавайте слои один раз, не на каждое событие. |
| `layer.set(target)` | Полностью заменяет цель слоя, сохраняя приоритет. Пропущенные ключи освобождаются нижним слоям. |
| `layer.clear()` | Временно снимает слой; следующий `set` возвращает его с прежним приоритетом. |
| `layer.destroy()` | Навсегда снимает слой и освобождает цель. Повторные вызовы безопасны; дальнейшие изменения игнорируются. |
| `state.batch(update)` | Объединяет синхронные изменения в одно итоговое уведомление. |
| `state.get(key)` / `state.snapshot()` | Читает текущее значение / возвращает новую поверхностно замороженную копию с прототипом `null`. |
| `state.subscribe(listener)` | Подписывает на будущие изменения без начального уведомления; возвращает функцию отписки. |
| `state.destroy()` | Очищает каскад и прекращает текущую и ожидающую доставку. Повторный вызов безопасен; слои становятся недействующими, уведомление об очистке не создаётся. |

### Значения и изменения

`T` может быть интерфейсом без индексной сигнатуры. Учитываются только собственные
перечислимые строковые ключи; значения могут быть нечисловыми. Исполнитель проверяет
их допустимость для движения. Вход копируется поверхностно: замена поля исходного
объекта не меняет слой, но вложенные объекты разделяются по ссылке и не должны меняться.

`set`, `clear` и `layer.destroy` возвращают замороженный объект `{ changed, removed }`.
`changed` содержит новые значения, `removed` — ключи без владельца. Собственный
ключ со значением `undefined` сохраняется в `changed` и снимке. Ключи соответствуют
`T`; обе коллекции заморожены поверхностно. Значения сравниваются через `Object.is`:
`NaN` равен себе, `-0` отличается от `+0`, смена владельца при равном значении
не уведомляет подписчиков. Постоянный базовый слой со всеми нужными ключами исключает
исчезновение свойства; иначе обработка `removed` принадлежит потребителю.

### Доставка и повторные вызовы

Изменения принимаются синхронно, уведомления доставляются по порядку принятия (FIFO).
Вложенный `set` из подписчика сразу виден через `get`/`snapshot`, но доставляется
после текущего уведомления. Применяйте его `{ changed, removed }`, не смешивая с более
новым снимком. Получатели фиксируются при принятии изменения; подписка и отписка
влияют только на последующие изменения. `state.destroy()` прекращает всю доставку.
Конечная цепочка не наращивает стек вызовов; бесконечная обратная связь не завершается.
Отдельные изменения не объединяются неявно, таймеров нет.

Синхронные исключения подписчиков не прерывают остальных: после доставки внешний
вызов выбрасывает исходную ошибку, несколько ошибок — `AggregateError` в порядке
возникновения. Принятые изменения не откатываются. Ошибка отложенного уведомления
вложенного вызова возвращается через внешний вызов, опустошающий очередь.

Чтение входа предшествует изменению. Исключение в геттере не создаёт частичную цель.
Успешный вложенный `set`/`clear`/`destroy` того же слоя отзывает устаревший внешний
`set`, который возвращает пустое изменение. Неудачное чтение вложенного входа или
изменение другого слоя не отменяет допустимый внешний вызов. `createLayer(initial)`
публикует слой после чтения входа, выше слоёв из его геттеров. При ошибке начальной
доставки недоступный вызывающему слой снимается с уведомлением; ошибка этой очистки
сохраняется вместе с исходной в `AggregateError`.

### Группировка через `batch`

`state.batch(() => { press.clear(); drag.set({ scale: 1.02 }); })` передаёт исполнителю
конечную цель без промежуточного базового значения. Чтение состояния и возвращаемые
изменения отдельных операций остаются синхронными. Внешняя группа публикует только
разницу исходной и конечной целей; возврат к исходному значению не уведомляет,
но сохраняет нового владельца. Вложенные группы входят во внешнюю; получатели
фиксируются на её выходе. Вызов из подписчика соблюдает общую очередь FIFO.

Это не транзакция с откатом: принятые изменения доставляются и при исключении
переданной функции, затем ошибка возвращается буквально, включая `undefined`.
Ошибка функции и ошибка доставки сохраняются в `AggregateError`. `destroy` внутри
группы отменяет её уведомление; после него `batch` не вызывает переданную функцию.
Граница синхронная: продолжения после `await` в группу не входят.

Каскад не выбирает переходы, не складывает анимации и не восстанавливает CSS.
[Пример с одним исполнителем, доступностью и очисткой](recipes.md#каскад-состояний-взаимодействия-без-гонок).
## Управляемая сортировка списков и сеток

Опциональный `@labpics/motion/behaviors/reorder` экспортирует `createReorder`.
Он не входит в barrel четырёх физических behaviors выше: это resolver порядка,
а не владелец value/velocity и не пятый движок движения. Приложение хранит данные,
resolver предлагает перестановку, существующий projection анимирует подтверждённый
layout. Поддержаны list/grid, pointer/keyboard, RTL, stable-key rebase и отзыв
устаревших предложений. Никаких DOM/физики/часов внутри.

Контракт и ограничения — [API](api.md#управляемая-перестановка-behaviorsreorder);
[прикладной рецепт](recipes.md#перестановка-списка-или-сетки) проверяется в браузерах.
Новый код поставляется только потребителю нового subpath.
