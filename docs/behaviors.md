# Behaviors-путь

> Роль: контракт `./behaviors` — headless state machines типовых мобильных
> взаимодействий и каскад целевых значений поверх примитивов движка.

Субпуть только оркеструет — ничего не дублируется: трекер скорости из
`./gestures`, проекция момента из `./decay`, пружинный солвер ядра,
темп-токены `./tokens`. Поведение не знает про фреймворк/компонентную
библиотеку: DOM-обвязка — тонкий адаптер поверх headless-API
(runnable-пример — [recipes.md](recipes.md)).

Общий контракт четырёх мобильных поведений: `BehaviorState { value, velocity, phase }`,
`phase ∈ 'idle' | 'follow' | 'release' | 'settle'`. Вход — `pointerDown`/
`Move`/`Up`/`Cancel` с точкой `{ x, y, t }` (`t` — секунды, напр.
`e.timeStamp / 1000`); выход — `state`-геттер + `subscribe`; программные
переходы и идемпотентные `cancel()` / `destroy()`.

## Четыре поведения

- **`createBottomSheet`** — snap-точки, rubber-band за крайними snap,
  программный `snapTo(index)`, перехват новым pointer-down.
- **`createDragDismiss`** — порог по смещению ИЛИ скорости, настраиваемое
  направление, возврат с унаследованной скоростью при недостигнутом пороге,
  детерминизм при `pointerCancel` (всегда домой, без закрытия).
- **`createCarousel`** — index выводится из position каждый кадр, inertia с
  доводкой к странице, RTL и вертикаль, `goTo`/`next`/`prev`.
- **`createPullToRefresh`** — резистентный overscroll, порог активации,
  `pending` БЕЗ второго владельца позиции (удержание — тот же единственный
  runner), возврат пружиной после async-действия.

Runnable DOM-адаптер bottom sheet (transform из headless-состояния, полная
связка pointer-событий, программный `snapTo`) — в [recipes.md](recipes.md).

## Ключевые свойства (все запинены тестами)

- **Один clock (одна state machine)**: pointer / programmatic control не плодят
  параллельных loops — единый generation-токен гасит stale-кадры, активен
  максимум один runner. Перехват pointer-down во время доводки → `follow` без
  утечки цикла.
- **C¹ на стыке follow→release**: скорость момента отпускания наследуется
  доводкой (`v0n = velocity / range` в пружинном солвере) — как smooth-pickup
  у `MotionValue`.
- **Выбор цели по положению+скорости**: snap/страница выбираются по проекции
  момента через `./decay` (`.rest`) — быстрый флик перепрыгивает snap;
  property-тесты (seeded-LCG) пинят «ближайший к decay-landing» на диапазоне
  value+velocity.
- **Reduced-motion = смена характера**: пространственная доводка снапает в
  цель МГНОВЕННО (ни одного кадра), состояние и результат сохранены — не
  «выключение».
- **Финитность и SSR-safe**: `value`/`velocity` всегда конечны (никогда
  NaN/∞, `-0` схлопнут — фаззинг-тест злого ввода), импорт не трогает
  window/document; единственный платформенный шов — инжектируемый
  `requestFrame` (детерминизм тестов).
- **`cancel()`/`destroy()` идемпотентны**: `destroy` делает вход инертным.


## Каскад визуальных намерений

`createStateCascade<T>()` разрешает одновременно активные визуальные намерения
покомпонентно. Это не пятая gesture-машина: у него нет `BehaviorState`, часов,
пружины, DOM или политики reduced-motion. Каскад выбирает **цели**; существующий
`MotionValue`, renderer или animation owner исполняет движение и его политику
доступности. Пример соединения — [recipes.md](recipes.md).

`T` может быть интерфейсом без index signature. Обрабатываются только собственные
перечислимые строковые ключи. Значения произвольные, не обязательно числовые:
проверка физической допустимости остаётся у исполнителя. Вход снимается shallow:
поздняя замена поля caller-объекта не меняет слой; вложенные объекты передаются по
ссылке и должны рассматриваться как неизменяемые значения.

| Операция | Контракт |
|---|---|
| `state.createLayer(initial?)` | Новый слой выше ранее опубликованных слоёв. Без initial он неактивен; `{}` активен, но не владеет ключами. Создавайте стабильные handles, а не новый слой на каждое событие. |
| `layer.set(target)` | Заменяет **всю** цель слоя; не patch-merge. Пропущенный прежний ключ освобождается нижнему владельцу. Приоритет слоя не меняется. |
| `layer.clear()` | Временно снимает слой. Следующий `set` возвращает его с прежним приоритетом. |
| `layer.destroy()` | Навсегда снимает слой, освобождает сохранённую цель. Handle остаётся инертным, повторный destroy безопасен. |
| `state.get(key)` / `state.snapshot()` | Текущая разрешённая цель. Snapshot — новая shallow-frozen копия с null prototype. |
| `state.subscribe(listener)` | Только будущие изменения эффективной цели, без initial emit. Возвращает функцию отписки. |
| `state.destroy()` | Терминально очищает каскад, отзывает все handles и обрывает уведомления, включая уже ожидающие доставки. Сам destroy не публикует patch. |

`set`, `clear` и `layer.destroy` возвращают immutable
`{ changed: Readonly<Partial<T>>, removed: readonly string[] }` с точными ключами
`T`. Отсутствие владельца — `removed`; собственный ключ со значением `undefined`
остаётся в `changed` и snapshot. Сравнение значений — `Object.is`: смена владельца
при равном значении не эмитит; `NaN` равен самому себе, `-0` отличается от `+0`.
И `changed`, и `removed` заморожены; неизменность вложенного значения остаётся
обязанностью caller.

Например, `press.scale = 0.97` перекрывает `hover.scale = 1.03`, но не
`selected.background`. `pointerleave` снимает только hover и не возвращает scale
в default поверх активного press. Изменения перекрытого base сохраняются без
уведомления; после снятия press раскрывается **последний**, а не исторический base.

### Реентрантность и ошибки

Изменение коммитится синхронно. Уведомления доставляются FIFO по порядку коммитов:
вложенный `set` из listener сразу виден через `get`/`snapshot`, но его patch
доставляется после завершения текущего уведомления. Patch описывает свой commit,
не обязательно самый поздний `snapshot` внутри реентрантного callback. Для
применения deltas используйте сам patch, не смешивайте его с новым snapshot.

Получатели фиксируются в момент commit. Подписка или отписка действует на
последующие commits, не на уже захваченных получателей; `state.destroy()` —
терминальное исключение, прекращающее и текущую, и отложенную доставку. Бесконечная
обратная связь, которая при каждом уведомлении создаёт новое различное значение,
не завершается; конечная цепочка не требует рекурсивного call stack. Асинхронного
scheduler и неявного объединения разных commits нет.

Синхронные исключения listeners не оставляют остальных потребителей со старой целью: доставка
заканчивается, затем внешний вызов выбрасывает исходное значение исключения;
несколько ошибок — `AggregateError` в порядке возникновения. Ошибка уведомления
не откатывает уже выполненный `set`/`clear`/`layer.destroy`. У реентрантного вызова
доставка отложена, поэтому ошибка listener возвращается через внешний вызов,
который опустошает очередь.

Getters входа выполняются до commit. Исключение getter не публикует частичную
цель. Более новый успешно принятый `set`, `clear` или `destroy` того же слоя из getter отзывает
устаревший pending `set`; этот устаревший вызов возвращает пустой patch. Неудачное
чтение вложенного входа не отзывает ещё допустимый внешний commit. Изменение
другого слоя не запрещает законный commit. `createLayer(initial)` публикует слой
после чтения initial, выше слоёв, созданных его getters. Если начальная доставка
бросает, недоступный caller слой снимается и rollback тоже доставляется. Ошибка
rollback не скрывает первоначальную — обе сохраняются в `AggregateError`.

Каскад не выбирает переходы, не сбрасывает CSS при исчезновении последнего
владельца и не реализует additive blending. Значение `removed` должно иметь явную
политику у потребителя; постоянный base со всеми нужными ключами избавляет
обычный interaction-сценарий от этой неоднозначности.
