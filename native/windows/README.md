# Экспериментальный канал Windows

`ScalarMotion` исполняет пружину LabMotion через Windows Composition. На поток UI
возвращаются события наблюдения; интегрирование и привязки свойств `Visual`
выполняются композитором. JS, локального интегратора и покадрового UI-таймера нет.

`Spring` принимает `ResponseMilliseconds > 0` и `0 <= Bounce < 1`.
Параметризация соответствует `src/motion/model.ts`: `ω = 2π·1000/response`,
`k = ω²`, `c = 2·(1 − bounce)·ω`. Штатный `InteractionTrackerInertiaMotion`
получает ускорение `−k·(x − target) − c·v` и интегрирует его сам.

Положение — в локальных единицах tracker; скорость — в тех же единицах в секунду.
Обычный конструктор сохраняет эти единицы. Для безразмерного прогресса используйте
`ScalarMotion.CreateProgress(compositor, initial)`: его значения находятся в
диапазоне 0…1, скорость измеряется в единицах прогресса в секунду. Внутренний
масштаб скрыт в адаптере. Пересчёт физических пикселей при смене DPI остаётся
отдельной задачей геометрии потребителя.

Координатный конструктор требует явные `initial` и `endpointAccuracy` в единицах
координаты. Потребитель переводит свой допустимый endpoint error в эти единицы:
для смещения это может быть половина физического пикселя, делённая на текущий
`RasterizationScale`; для проекции `q = -y / H` точность `0.001` по q даёт
`endpointAccuracy = 0.001 * H`. Значение должно быть положительным и конечным,
а его квадрат — представимым в единицах исполнителя. `CreateProgress` задаёт
ранее квалифицированную точность `0.001` самостоятельно.

```csharp
using var motion = ScalarMotion.CreateProgress(visual.Compositor);
using var binding = motion.Bind(visual, ScalarProperty.Opacity);
await motion.AnimateTo(1, new Spring(350, 0));
```

`Bind` поддерживает `OffsetX`, `OffsetY` и `Opacity`. Выражение
`position * multiplier + offset` вычисляется композитором в публичных единицах
канала. Геометрия и степень эффекта принадлежат потребителю. `BindOffsetX` —
сокращение для прямой координатной привязки.

У каждой пары Visual/свойство одна активная привязка LabMotion. Повторный `Bind`
заменяет её; освобождение старого handle или канала не останавливает новую.
Другие свойства не затрагиваются. Handle и канал освобождаются на потоке
владельца. Перед прямой записью свойства или запуском чужой Composition-анимации
освободите его привязку LabMotion: произвольную внешнюю замену адаптер не отслеживает.
Для visual из `ElementCompositionPreview.GetElementVisual` это относится и к XAML:
он может записать локальное значение свойства при следующем layout tick и снять
анимацию. В примере Opacity оставлена в XAML по умолчанию, начальную прозрачность
задаёт канал прогресса. См. [правила совместного владения visual](https://github.com/microsoft/WindowsCompositionSamples/wiki/XAML-Composition-Interop-Behavior-Changes).

Один экземпляр принадлежит потоку с `DispatcherQueue`. `AnimateTo` заменяет
предыдущую операцию с результатом `Stopped/replaced`. При retarget из Inertia
текущие позиция и скорость сохраняются. Явная начальная скорость допустима из
покоя, когда нет активной операции. `SnapTo`, `Stop` и `Dispose` различаются
причиной результата; только native Idle активного request завершает его как
`Finished/settled`. Это штатный порог покоя Windows, не обещание математически
точного равенства координаты цели. Requests, устаревшие callbacks и bindings
принадлежат адаптеру. Ошибка native admission отклоняет Task.

## Ввод в сырой координате

Координатный конструктор принимает `ScalarAxis.X` или `ScalarAxis.Y`. Ось
одновременно определяет bounds, силу, скорость, наблюдения и привязки.
Для вертикального viewport `Position` совпадает с native Y; обычно визуальное
смещение имеет противоположный знак:

```csharp
using var motion = new ScalarMotion(viewport.Compositor, ScalarAxis.Y, -640, 320,
    initial: 0, endpointAccuracy: 0.001f * 320);
motion.SetTarget(-320, new Spring(350, 0));
using var binding = motion.Bind(content, ScalarProperty.OffsetY, -1);
using var pan = motion.AttachPan(viewport);
// В Touch PointerPressed: pan.Redirect(args.GetCurrentPoint(null));
```

Границы в примере относятся к viewport высотой 320 DIP. Геометрия остаётся
у потребителя. `AttachPan` требует явно заданную цель и пружину; `CreateProgress`
к вводу не подключается, поскольку native drag и release работают в сырых
координатах. Безразмерный progress можно получить проекцией сырой координаты.

`SetTarget` меняет цель и пружину текущей Inertia и следующего отпускания без
запроса запуска. Его можно вызывать во время drag. Ожидание прежней программной
анимации заканчивается `Stopped/target-changed`, поэтому оно не подтвердит
достижение уже заменённой цели. `AnimateTo` объединяет установку намерения с
попыткой запуска; `RequestIgnored` отклоняет эту попытку, сохраняя намерение.
Проверка фазы на UI-потоке не делает асинхронные настройки и native Try атомарными.

`Observed.Origin` различает `Animation`, `Input`, `Initial`, `Snap` и `Stop`.
Ввод поступает и без ожидающей Task; его `Operation` равен 0 и не завершает чужую
программную операцию. Поля `NativeRequestId`, `NativePosition`,
`NativeReadbackPosition` и `NativeVelocityVector` сохраняют исходные данные WinUI
для диагностики. Управление компонентом не требует этих идентификаторов.

`SnapTo` и `Stop` отправляют команду и прекращают локальное ожидание прежней
анимации. `requested` означает отправку; `value`, `idle` или `ignored` передают
реально полученный callback. Для no-op callback может отсутствовать: общего
обещания native ACK и публичного `Ready` нет. Ненулевой старт Touch-примера
ожидает `Initial/value` с фактической позицией и readback перед приёмом ввода.

Viewport должен оставаться неподвижным. Handle `ScalarPan` принадлежит потоку
канала; его `Dispose` отключает источник и публичные input-наблюдения, но не
обещает остановки уже начатой Inertia. Внутренняя фаза продолжает учитывать
native callbacks. `ScalarMotion.Dispose` освобождает источники и визуальные
привязки, завершает ожидающую Task и подавляет поздние наблюдения.

## Область опыта

Проверены Windows 11 build 26200, Windows App Runtime 2.6.4, .NET 10.0.403,
WinUI x64 unpackaged и масштаб 1.5. Проверка запускает реальные программные
сценарии в WinUI Window: движение до ±200, retarget после ±40 к ∓100,
сохранение ненулевой скорости против варианта со сбросом, спокойную пружину,
начальную скорость 600, Stop, SnapTo и Dispose. События берут значение из
`InteractionTrackerValuesChangedArgs.Position`; `ReadbackPosition` отдельно
читает `InteractionTracker.Position.X`. Эти сценарии проверяют координату
tracker и завершение операций. Видимое смещение привязанного `Visual` требует
отдельной проверки кадров.

Это не публикуемый пакет (`IsPackable=false`). Жесты sheet, смена DPI/геометрии
и производственные потребительские гарантии ещё требуют реализации и проверки.
Калибровки и стили потребителя в библиотеку не входят.

## Воспроизведение

В репозитории находятся настоящий WinUI-потребитель
[`examples/windows`](../../examples/windows/) и
[`test/windows/verify.ps1`](../../test/windows/verify.ps1). Нужны Windows с
доступным Composition, .NET SDK 10.0.403 и PowerShell. Точная версия SDK и
`rollForward: disable` закреплены в [`global.json`](../../test/windows/global.json).
Из корня репозитория:

```powershell
pwsh -File test/windows/verify.ps1 -OutputDirectory "$env:TEMP/motion-windows-run"
```

Каталог результата должен быть новым. Проверка собирает lifecycle-пробы
и запускает одиннадцать сценариев в настоящем WinUI Window. В lifecycle-пробах
подменена только граница Composition; интегрирование проверяется отдельным
WinUI-потребителем. Сброс скорости служит контролем для retarget, а вызовы
из Idle observer проверяют окончательность результата завершённого движения.

Приложение поставляет .NET и Windows App SDK вместе с собой; глобальная установка
App Runtime не требуется. Параметры пружин — данные примера, без зависимости
от другой дизайн-системы. Скрипт проверяет код завершения, полный состав
сценариев и наличие нативных событий. Недоступный runtime, таймаут и отсутствующий
trace завершают проверку ошибкой. Журналы сборки, trace, результаты и хеши
исполняемых файлов сохраняются в каталоге результата.

Без `LAB_MOTION_PROBE_OUTPUT` приложение открывает интерактивный пример нажатия.
Он наблюдает штатный `Button.IsPressed`, поэтому мышь, клавиатура и отмена ввода
остаются в ведении WinUI. Пример использует opacity-привязку, учитывает системное
отключение анимаций и локальный переключатель, снимает подписки при `Unloaded`.
Это технический пример LabMotion, без стилей и токенов внешней дизайн-системы.

Проверку ввода запускают после сборки consumer, в отдельной интерактивной
Windows-сессии с PowerShell 7 и Node:

```powershell
pwsh -File test/windows/verify-input.ps1 -ApplicationDirectory "$env:TEMP/motion-windows-run/app" -OutputDirectory "$env:TEMP/motion-input-run"
```

Скрипт скачивает официальный winapp CLI 0.7.1 с проверкой SHA256, запускает своё
окно и передаёт ему мышь и Space через системный ввод. Он требует события
WinUI, промежуточные значения движения и возврат в покой. Локальный переключатель
проверяется отдельно. Обычный запуск требует уже включённой системной анимации.
Флаг `-ConfigureHostedAnimations` доступен только в одноразовой GitHub-hosted
сессии: он включает client-area animation через `SystemParametersInfo`, проверяет
readback и восстанавливает прежнее значение при завершении. Профиль пользователя
на диск не записывается; приложение продолжает учитывать `UISettings`.
Кадры WGC и снимки окна сохраняются для визуального review. Автоматический
результат описывает ввод и движение; качество изображения проверяется по кадрам.

Для этого запуска `LAB_MOTION_PRESS_TRACE` включает ограниченную JSONL-трассу
в примере. Обычный запуск не регистрирует диагностические наблюдатели и не пишет
на диск. CLI используется только тестом и не входит в библиотеку.
Официальная [документация Microsoft](https://learn.microsoft.com/en-us/windows/apps/develop/ai-assisted/testing)
описывает этот путь для GitHub Windows runner. Сам факт запуска на runner
не подтверждает touch, потерю capture, смену DPI или удержание Space:
этим сценариям нужны отдельные наблюдения.

## Точность прогресса

В предварительном опыте сырая координата 0…1 получала native Idle до достижения
цели с требуемой точностью. `CreateProgress` использует внутренний размах 1000,
сохраняя позицию и скорость в публичных единицах. Это смена единиц существующей
пружины, без второго интегратора и без принудительного скачка в конце анимации.

Нативные проверки задают допуск 0.001 для переходов 0→1, 1→0 и разворота на ходу;
также проверяют промежуточные значения, сохранение скорости и явную начальную
скорость. Допуск относится к этим сценариям и указанной среде. Он не является
доказательством для всех параметров пружины и версий Windows; число 1000
не объявляется оптимальным.

## Завершение у границы

`Inertia` допускает выход за `MinPosition` / `MaxPosition`, а `Idle` требует
возврата внутрь. При безусловном выборе custom force нативный интегратор может
остановиться на малом остатке снаружи и повторно выбирать ту же пружину вместо
штатного возврата в границы. Границы и формула силы поэтому остаются прежними,
а выбор модификатора уступает штатной коррекции только при трёх условиях:
позиция снаружи, цель совпадает именно с этой границей, остаточная энергия
пружины укладывается в заданную точность координаты.

Для `d = x - target`, `k > 0`, `c > 0` величина `A² = d² + v²/k` имеет
производную `-2c·v²/k <= 0`. Следовательно, `A` ограничивает остаточное отклонение
идеальной затухающей пружины с неизменной целью. Условие `A² <= accuracy²`
проверяется самим композитором при выборе Inertia modifier. Оно сохраняет
заданную пружину при раннем развороте, ненулевой значительной скорости и новой
внутренней либо противоположной цели. Точность переводится вместе с позицией
и скоростью; у адаптера нет скрытого допуска в DIP.

Это обоснование момента передачи управления, а не отдельный интегратор или
доказательство траектории штатной коррекции. Нативные проверки требуют реального
`Idle` нужного request, конечной позиции в исходном диапазоне и заданного
endpoint error. Адаптер не подменяет `Finished`, не расширяет bounds и не ждёт
покоя по таймеру.

## Почему используется force expression

`SpringScalarNaturalMotionAnimation` с natural modifier в проверенном runtime
сбрасывала позицию и скорость при программном повторном входе в Inertia.
Это воспроизведено также с новым spring object и начальным выражением из tracker.
Её `Period` дополнительно оказался в 2π раз медленнее параметра LabMotion
`response` при одинаковом численном значении. Эти отрицательные результаты
не переносятся на другие версии ОС без повторной проверки.

[Официальный контракт InteractionTrackerInertiaMotion](https://learn.microsoft.com/en-us/windows/windows-app-sdk/api/winrt/microsoft.ui.composition.interactions.interactiontrackerinertiamotion)
прямо задаёт вторую производную позиции и содержит пример силы пружины;
[TryUpdatePositionWithAdditionalVelocity](https://learn.microsoft.com/en-us/windows/windows-app-sdk/api/winrt/microsoft.ui.composition.interactions.interactiontracker.tryupdatepositionwithadditionalvelocity)
добавляет скорость в Inertia. Адаптер передаёт ноль при retarget и сохраняет
состояние системного исполнителя.
